# BRAND GRODNO

Магазин одежды, обуви и аксессуаров BRAND GRODNO в Telegram Mini App.

## Запуск на Mac — простая инструкция

Следуйте шагам по порядку. Команды нужно вводить в приложение **Терминал**
(откройте его через `⌘ + пробел`, затем напечатайте «Терминал»). После
введения команды нажимайте `Return`. Если команда продолжает выводить текст и
курсор не вернулся, она работает — оставьте это окно открытым.

Этот вариант подходит для проверки магазина: компьютер должен быть включён и
не переходить в режим сна, а четыре окна Терминала с API, сайтом, HTTPS-ссылкой
и ботом должны оставаться открыты.
Временная ссылка может измениться после перезапуска. Для постоянной работы
магазина понадобится VPS — это отдельный, более сложный раздел ниже.

### 1. Установите нужные программы

Нужны Homebrew, Python, Node.js и Cloudflare Tunnel. Homebrew — это программа,
которая устанавливает остальные инструменты на Mac.

1. Если Homebrew ещё не установлен, откройте его официальный сайт
   [brew.sh](https://brew.sh/) и выполните показанную там команду установки.
   Если не уверены, что установка завершилась, попросите помочь на этом шаге.
2. Откройте Терминал и вставьте:

   ```sh
   brew install python@3.12 node cloudflared
   ```

3. Проверьте, что программы установились:

   ```sh
   python3.12 --version
   node --version
   npm --version
   cloudflared --version
   ```

   Каждая команда должна показать номер версии. Если Терминал пишет
   `command not found`, вернитесь к установке соответствующей программы.

### 2. Создайте бота и сохраните настройки

1. Откройте Telegram и найдите **@BotFather** — это официальный бот Telegram
   для управления ботами.
2. Если бот уже создан, отправьте ему `/revoke`, выберите своего бота и
   получите новый токен. Ранее отправленный в переписке токен использовать
   нельзя: он мог стать известен другим людям. Если бота ещё нет, отправьте
   `/newbot`, придумайте имя и username, который заканчивается на `bot`.
3. Скопируйте новый токен временно в заметку на своём Mac. Никому его не
   отправляйте и не публикуйте скриншоты с токеном.
4. Узнайте свой **числовой Telegram ID** и ID менеджера. Это именно цифры, не
   имя с `@`. Их можно узнать, написав в Telegram боту **@userinfobot**.
   Если вы сами будете менеджером, для обоих значений используйте один и тот
   же ID.
5. В Терминале перейдите в папку проекта. Для этой копии проекта команда такая:

   ```sh
   cd "/Users/macount/Documents/bot telegramm"
   ```

   Если вы переместили папку проекта, наберите `cd ` (с пробелом после `cd`),
   перетащите папку проекта из Finder в окно Терминала и нажмите `Return`.
6. Создайте файл настроек:

   ```sh
   cp .env.example .env
   open -e .env
   ```

   Если файл `.env` уже существует и вы раньше его настраивали, **не
   выполняйте `cp` повторно** — просто откройте его командой `open -e .env`,
   чтобы не затереть настройки.
7. В открывшемся TextEdit замените только значения этих строк:

   ```text
   BOT_TOKEN=сюда_вставьте_новый_токен
   ADMIN_IDS=сюда_вставьте_свой_числовой_ID
   MANAGER_TELEGRAM_ID=сюда_ID_менеджера
   ```

   Не вставляйте слова «сюда» или пробелы вокруг `=`. Не меняйте остальные
   строки. Нажмите `⌘ + S`, чтобы сохранить, затем закройте TextEdit. Файл
   `.env` хранит секреты на вашем компьютере — не отправляйте его другим.

### 3. Запустите API (окно Терминала № 1)

Скопируйте блок целиком в Терминал:

```sh
cd "/Users/macount/Documents/bot telegramm/backend"
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
export DATABASE_URL="sqlite+aiosqlite:///./local-catalog.db"
python -m app.db.dev
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

При первой установке команда загрузки библиотек может выполняться несколько
минут. В конце должно появиться сообщение, что сервер запущен на порту 8000.
**Не закрывайте это окно.** Чтобы проверить API, откройте Safari и перейдите
на [http://localhost:8000/health](http://localhost:8000/health). Должно
показаться `{"status":"ok"}`.

### 4. Запустите сайт (окно Терминала № 2)

Откройте ещё одно окно Терминала: нажмите `⌘ + N`. Введите:

```sh
cd "/Users/macount/Documents/bot telegramm/frontend"
npm ci
npm run dev
```

При первой установке дождитесь её окончания. Сайт работает по адресу
[http://localhost:5173](http://localhost:5173). Оставьте это окно открытым.
Если в папке `frontend` есть свой файл `.env`, значение
`VITE_API_BASE_URL` должно быть пустым, иначе сайт на телефоне не найдёт API.

### 5. Получите HTTPS-ссылку (окно Терминала № 3)

Telegram не открывает Mini App по обычному адресу `localhost`, поэтому нужна
временная защищённая HTTPS-ссылка.

1. Откройте третье окно Терминала (`⌘ + N`) и запустите:

   ```sh
   cloudflared tunnel --url http://localhost:5173
   ```

2. Подождите, пока в тексте появится адрес, который начинается с
   `https://` и заканчивается на `.trycloudflare.com`. Не закрывайте это
   окно — пока оно открыто, ссылка работает.
3. Скопируйте адрес. Например, если вам показали
   `https://example.trycloudflare.com`, откройте в Safari адрес
   `https://example.trycloudflare.com/health`. Должно показаться
   `{"status":"ok"}`. Везде ниже используйте именно ваш адрес, а не пример.

### 6. Впишите ссылку и запустите бота (окно Терминала № 4)

1. Вернитесь в Терминал и откройте настройки:

   ```sh
   cd "/Users/macount/Documents/bot telegramm"
   open -e .env
   ```

2. Найдите строку `MINI_APP_URL=...`, замените всё после `=` на HTTPS-ссылку
   из предыдущего шага, сохраните файл (`⌘ + S`) и закройте TextEdit.
   Пример формата: `MINI_APP_URL=https://example.trycloudflare.com`.
3. Откройте четвёртое окно Терминала (`⌘ + N`) и запустите бота:

   ```sh
   cd "/Users/macount/Documents/bot telegramm/backend"
   source .venv/bin/activate
   export DATABASE_URL="sqlite+aiosqlite:///./local-catalog.db"
   python -m app.bot.main
   ```

   Если появилось сообщение об ошибке, не закрывайте окно: текст ошибки
   поможет понять, что нужно исправить. Если бот запустился, окно оставьте
   открытым. При запуске он сам установит кнопку меню **«Открыть каталог»**.

### 7. Проверьте магазин в Telegram

1. Найдите своего бота по username в Telegram и откройте чат.
2. Нажмите **Start** или отправьте `/start`.
3. Нажмите кнопку **«Открыть каталог»**.
4. Проверьте, что открывается магазин и видны демонстрационные товары.
5. Если вы назначили себя администратором, откройте профиль в приложении и
   найдите **«Панель управления»**. Перед настоящими заказами замените в
   настройках магазина примеры контакта менеджера, ссылки на отзывы и
   стоимости доставки.

Менеджер и каждый администратор должны сами открыть чат с ботом и отправить
`/start`. Иначе Telegram не позволит боту первым прислать им уведомление о
заказе.

### Если вы остановили запуск

- Остановить любой работающий процесс можно сочетанием `Control + C` в его
  окне Терминала.
- Чтобы запустить магазин снова, откройте четыре окна и повторите шаги 3–6.
  Команду `npm ci` при повторном запуске можно пропустить.
- Если Cloudflare выдал новый HTTPS-адрес, обновите `MINI_APP_URL` в `.env`
  и перезапустите бота. Старый адрес больше не будет открывать магазин.
- Адрес `http://localhost:5173` работает только на вашем Mac. Для телефона
  открывайте магазин из чата с ботом в Telegram.

### Настройка имени и описания бота в BotFather

Это необязательно для первого запуска. Чтобы добавить логотип и описание,
откройте **@BotFather** → `/mybots` → выберите бота → **Edit Bot**. Там можно
изменить описание, короткий текст и фотографию бота. Если кнопка **«Открыть
каталог»** не появилась, отправьте `/setmenubutton`, выберите бота, укажите
текст `Открыть каталог` и тот же актуальный HTTPS-адрес.

## Запуск для постоянной работы

### Docker Compose, PostgreSQL и автоматический HTTPS

Нужны Docker Engine с Compose plugin, домен и VPS с открытыми входящими портами
80/443. Укажите DNS-записи домена на публичный IP VPS до старта Caddy. В
корневом `.env` задайте:

- новый `BOT_TOKEN`, `ADMIN_IDS` и `MANAGER_TELEGRAM_ID`;
- `POSTGRES_PASSWORD` — сгенерируйте URL-безопасный пароль:
  `openssl rand -hex 32`;
- `DOMAIN`, `ACME_EMAIL`, `MINI_APP_URL=https://ваш-домен`,
  `PUBLIC_BASE_URL=https://ваш-домен` и
  `CORS_ORIGINS=https://ваш-домен`.

Запустите все сервисы из корня проекта:

```sh
docker compose -f docker-compose.yml up --build -d
docker compose -f docker-compose.yml ps
docker compose -f docker-compose.yml logs -f api bot caddy
```

Compose запускает PostgreSQL, API и Telegram-бот отдельными контейнерами,
frontend-контейнер с production-сборкой, а Caddy принимает HTTP/HTTPS,
автоматически получает и продлевает TLS-сертификат. Caddy направляет
`/api/*`, `/health`, `/docs`, `/openapi.json` и `/uploads/*` на API, остальные
пути — на frontend. Порт API не публикуется напрямую. Миграции и идемпотентный
сидер запускаются перед стартом API. PostgreSQL, загруженные фотографии и
сертификаты Caddy хранятся в отдельных Docker volumes.

Проверка после запуска:

```sh
curl -fsS https://ваш-домен/health
```

Ожидаемый ответ — `{"status":"ok"}`. Для остановки без удаления данных
используйте `docker compose -f docker-compose.yml down`. Не добавляйте `-v`:
эта опция удаляет volumes с базой и файлами.

Создайте резервную копию базы и изображений после запуска сервисов:

```sh
./scripts/backup.sh
```

Скрипт сохраняет SQL-дамп и архив `uploads` в `backups/` (или в каталог,
указанный первым аргументом). Копируйте резервные копии на отдельное хранилище
и регулярно проверяйте восстановление. SQL можно восстановить через
`docker compose -f docker-compose.yml exec -T db sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" psql --username="$POSTGRES_USER" --dbname="$POSTGRES_DB"' < dump.sql`;
архив изображений распакуйте в volume командой
`docker compose -f docker-compose.yml exec -T api tar -xzf - -C /app < uploads-backup.tar.gz`.

### Переезд на недорогой VPS

1. Арендуйте VPS с Ubuntu LTS/Debian, установите Docker Engine и Compose plugin.
   Разрешите входящие TCP-порты 22, 80 и 443 (443/UDP необязателен для HTTP/3).
2. Купите домен или используйте свой. Создайте DNS A-запись для `@` (и при
   необходимости `www`) на IP VPS. Не добавляйте AAAA, если у VPS нет рабочего
   IPv6.
3. Получите проект на VPS, например через Git, и создайте корневой `.env` из
   `.env.example`. Заполните все обязательные Telegram-поля, пароль БД, домен,
   email ACME и публичные URL. Не переносите локальную SQLite-базу в production.
4. Установите и запустите production-стек. На чистом сервере Compose сам
   дождётся PostgreSQL, применит миграции и добавит начальные настройки:

   ```sh
   docker compose -f docker-compose.yml up --build -d
   docker compose -f docker-compose.yml logs -f api caddy
   ```

   При отдельном контролируемом применении схемы после остановки API можно
   остановить API и бота, затем запустить команды по очереди:

   ```sh
   docker compose -f docker-compose.yml stop api bot
   docker compose -f docker-compose.yml run --rm api python -m alembic upgrade head
   docker compose -f docker-compose.yml run --rm api python -m app.db.seed
   docker compose -f docker-compose.yml up -d api bot caddy
   ```

   Не запускайте миграцию параллельно с работающим API.
5. Проверьте DNS, `https://ваш-домен/health`, `/docs`, `/start` бота и откройте
   Mini App в Telegram. Для обновления используйте
   `docker compose -f docker-compose.yml up --build -d`; до важных обновлений
   сохраните backup.
6. Настройте расписание резервного копирования, например cron каждый день в
   03:00: `0 3 * * * /полный/путь/к/проекту/scripts/backup.sh`. Настройте
   ротацию и копирование архивов за пределы VPS.

### Как владельцу добавить первый товар

Откройте бота в Telegram от имени пользователя, включённого в `ADMIN_IDS`,
нажмите **Открыть каталог** и перейдите в **Профиль → Панель управления**.
Откройте вкладку **Каталог**, при необходимости проверьте категории и размеры,
затем **Товары → Добавить товар**. Заполните название, категорию, секцию,
размеры и их остатки, цены BYN (и при необходимости ручную цену RUB), отметку
«Новый» и фотографии. В форме фото можно выбрать несколько снимков из галереи
телефона или сделать их камерой; перетаскивание и кнопки порядка меняют
обложку. Нажмите **Опубликовать**. После этого откройте карточку товара в
магазине и проверьте размеры, цены и фото.

Перед запуском для покупателей измените в **Настройки** имя менеджера,
ссылку на отзывы, тексты и цены доставки. Значения из сидера — примеры, а
`your_manager` и `your_reviews_channel` не являются контактами вашего магазина.

```text
    api/                HTTP-маршруты, зависимости и Pydantic-схемы

  Dockerfile            Образ API
  Dockerfile.bot        Образ Telegram-бота
frontend/
  src/
    app/                Каркас маршрутов и приложения
    components/ui/      Общие UI-компоненты
    lib/                API-клиент и React Query
    telegram/           Telegram SDK и кнопки Mini App
  package.json          Зависимости и команды frontend
  Dockerfile            Production-сборка и nginx static server

.env.example            Пример переменных окружения
```

## База данных

- `users` — Telegram-пользователи.
- `categories` — категории с поддержкой вложенности.
- `places` — организации и услуги с контактами, адресом, координатами,
  графиком работы, фотографиями и кешем рейтинга.
- `reviews` — оценки и отзывы.
- `favorites` — избранные места пользователя.
- `submissions` — предложения и изменения на модерацию.
- `products` — товары с категорией, ценой в BYN, вариантами размеров и цветов,
  фотографиями-заглушками и датой продажи `sold_at`.
- `store_settings` — редактируемые настройки магазина, включая менеджера,
  ссылку на отзывы, курс BYN/RUB и тексты для покупателей.
- `delivery_methods` — способы доставки с редактируемыми ценой и признаком
  активности.

Исходную схему создаёт миграция
`backend/alembic/versions/0001_initial_schema.py`; магазинные таблицы и товары
добавляет `backend/alembic/versions/0002_store_products_and_settings.py`, а
поле фотографии Telegram-профиля — миграция
`backend/alembic/versions/0003_user_photo_url.py`. Очередь уведомлений Telegram
добавляет `backend/alembic/versions/0005_notification_outbox.py`; поля
ручных цен RUB, отметка «новинка» и справочник размеров добавлены миграцией
`backend/alembic/versions/0006_admin_catalog.py`.
Рейтинг и количество отзывов в записи места являются кешем. Настройки хранятся
в единственной строке `store_settings`; цены доставки по договорённости
хранятся как `price_byn = NULL` с пояснением в `price_note`.

После миграций заполните начальные настройки и демонстрационный каталог:

```sh
cd backend
python3 -m app.db.seed
```

Сидер можно запускать повторно: он добавляет записи только при отсутствии
уникального ключа и не перезаписывает настройки, товары или способы доставки,
которые уже были отредактированы.

## Backend и бот

Для локальной разработки с SQLite и туннелем используйте пошаговую инструкцию
в разделе [Stage 9 — запуск](#stage-9--запуск). Инициализатор
`python -m app.db.dev` создаёт SQLite-схему и заполняет демо-каталог; SQLite
предназначена для одного локального разработчика и не заменяет PostgreSQL.

Для PostgreSQL установите зависимости, примените миграции и запустите сидер:

```sh
python3 -m pip install -r backend/requirements-dev.txt
cd backend
python3 -m alembic upgrade head
python3 -m app.db.seed
```

Для локального запуска API и frontend смотрите Stage 9. Для production
используйте `docker compose -f docker-compose.yml up --build -d`: Compose
применяет миграции и сидер автоматически. Не используйте токен, ранее
опубликованный в переписке: отзовите его в BotFather и выпустите новый.

Запуск тестов backend: `cd backend && python3 -m pytest -q`.

Проверка доступности API: `GET /health`. Документация FastAPI доступна по адресу
`/docs`.

Mini App передаёт исходный `initData` в заголовке `X-Telegram-Init-Data`.
Backend проверяет HMAC-подпись и срок `auth_date`; при первом обращении
создаётся пользователь, затем обновляются его username и фотография профиля.
Список администраторов задаётся в `.env` через `ADMIN_IDS`; числовой
`MANAGER_TELEGRAM_ID` нужен, чтобы бот мог отправлять менеджеру уведомления.
Загруженные файлы
раздаются с `/uploads/`; каталог задаётся переменной `UPLOADS_DIR` (по умолчанию
`uploads/` в корне проекта). `GET /health` проверяет доступность процесса API.

## Telegram-бот и уведомления

- Кнопка меню Telegram и `/start` открывают Mini App; приветствие, четыре шага,
  условия доставки, ссылка на отзывы и username менеджера берутся из настроек
  магазина и способов доставки.
- `/orders` показывает последние заказы пользователя. `/admin` отправляет
  ссылку на Mini App; право доступа к панели отдельно проверяется по `ADMIN_IDS`.
- Новый заказ и уведомление о смене статуса записываются в transactional
  outbox в той же транзакции, что и изменение заказа. Бот доставляет события
  отдельно и повторяет временно неудачные отправки.
- Подтверждение заказа списывает остатки под блокировкой строк и в транзакции;
  отмена подтверждённого заказа возвращает остатки. Кнопки статуса доступны
  менеджеру и администраторам.

## Store API

Маршруты магазина описаны в OpenAPI (`/docs`). Защищённые маршруты требуют
заголовок `X-Telegram-Init-Data`.

- `GET /api/store/categories?group=clothing|shoes` — категории одежды или обуви.
- `GET /api/store/products` — поиск и фильтрация по названию/бренду, секции,
  группе, категории, размеру, цене и валюте, наличию и скидке. Сортировка:
  `newest`, `price_desc`, `price_asc`; пагинация — `page` и `page_size`.
- `GET /api/store/products/{product_id}` — карточка товара с вариантами и
  остатками.
- `GET /api/me/preferences` и `PUT /api/me/preferences` — чтение и сохранение
  предпочитаемых секции и валюты (`BYN` или `RUB`).
- `GET /api/store/favorites`, `PUT /api/store/favorites/{product_id}` и
  `DELETE /api/store/favorites/{product_id}` — избранные товары.
- `GET /api/cart`, `POST /api/cart/items`, `PATCH /api/cart/items/{variant_id}`
  и `DELETE /api/cart/items/{variant_id}` — корзина; остатки проверяются при
  каждом изменении. Не более восьми разных вариантов одновременно.
- `POST /api/orders` — оформление заказа; при успехе ответ содержит
  `manager_link`. `GET /api/orders` и `GET /api/orders/{order_id}` — список и
  детали покупок.
- `GET /api/store/settings` и `GET /api/store/delivery-methods` — публичные
  настройки, менеджер, ссылка на отзывы и активные способы доставки с ценами.

В заказе для доставки курьером требуются город и полный адрес; для почтовых
служб и СДЭК — город и адрес или отделение. Наличие проверяется при оформлении,
а остатки списываются в транзакции при подтверждении заказа менеджером.
Корзина очищается после успешного оформления. Цены в RUB рассчитываются из
цены в BYN по курсу настроек магазина.

## Admin API

Все маршруты `/api/admin/*` защищены проверкой Telegram `initData` и доступны
только ID из `ADMIN_IDS`.

- `GET/POST /api/admin/products`, `PUT/DELETE /api/admin/products/{id}` —
  список, создание, полное изменение и удаление товаров;
  `PATCH /api/admin/products/{id}/visibility?is_active=true|false` — показать
  или скрыть товар. Поля товара: название, бренд, описание, секция, категория,
  цена в BYN, ручная или вычисленная по курсу цена в RUB, старая цена для скидки,
  размеры с остатками и флаг «новинка». При скидке `price_byn` задаёт текущую
  цену, а `old_price_byn` — прежнюю; для ручной RUB-цены задайте
  `rub_price_mode: "manual"` и `price_rub`.
- `POST /api/admin/products/{id}/images` принимает несколько JPEG/PNG/WebP
  (до 10 МБ на файл, не более 20 изображений на товар), преобразует в WebP,
  ограничивает ширину 1600 px и сохраняет миниатюру. `PUT
  /api/admin/products/{id}/images/order` задаёт порядок и обложку; `DELETE
  /api/admin/products/{id}/images/{image_id}` удаляет изображение.
- `/api/admin/categories` и `/api/admin/size-options` предоставляют список и
  CRUD категорий/размеров. Категорию нельзя удалить, пока к ней привязаны
  товары, места или дочерние категории. Сидер добавляет базовые варианты
  размеров одежды и обуви, их список можно редактировать через Admin API.
- `GET /api/admin/orders?status=pending` — фильтруемый список заказов;
  `GET /api/admin/orders/{id}` — подробности; `PATCH
  /api/admin/orders/{id}/status` принимает `confirm`, `shipped`, `delivered`
  или `cancel` и использует общую с ботом транзакционную логику склада и
  уведомлений.
- `GET/PATCH /api/admin/settings` — настройки магазина и курс BYN/RUB.
  `GET/POST /api/admin/settings/delivery-methods` и `PUT/DELETE
  /api/admin/settings/delivery-methods/{id}` управляют доставкой и её ценой.

Загруженные изображения сохраняются внутри `UPLOADS_DIR`; Docker Compose
подключает для этого общий постоянный volume API и боту.

## API мест (legacy)

Все маршруты описаны в OpenAPI и доступны в Swagger UI по адресу `/docs`.
Защищённые маршруты требуют заголовок `X-Telegram-Init-Data`.

- `GET /api/categories` — активные категории.
- `GET /api/places` — опубликованные места; параметры `search`, `category_id`,
  `district`, `min_rating`, `open_now`, `sort`, `limit`, `cursor`.
- `GET /api/places/{place_id}` — карточка места.
- `GET /api/places/{place_id}/reviews` и `POST /api/places/{place_id}/reviews` —
  список отзывов и создание отзыва с оценкой от 1 до 5.
- `GET /api/favorites` — избранное текущего пользователя.
- `PUT /api/favorites/{place_id}` и `DELETE /api/favorites/{place_id}` —
  добавить место в избранное или удалить его.
- `POST /api/submissions` — отправить новое место на модерацию.

Сортировка каталога: `newest` (по умолчанию), `rating`, `name`. Пагинация
каталога использует keyset-курсор: следующая страница запрашивается с курсором
`next_cursor` из предыдущего ответа и теми же фильтрами.

Часовой пояс для фильтра `open_now` задаётся переменной `CITY_TIMEZONE`
(по умолчанию `Europe/Minsk`). График работы хранится как JSON-объект с ключами
`monday`–`sunday` и массивами локальных интервалов, например:

```json
{
  "monday": [{"open": "09:00", "close": "18:00"}],
  "sunday": []
}
```

Тесты можно запустить из каталога `backend`:

```sh
python3 -m unittest discover -s tests -v
```

## Frontend

Требуется Node.js `22.22` или новее. Создайте `frontend/.env` на основе
`frontend/.env.example`, затем из каталога `frontend` выполните:

```sh
npm install
npm run dev
```

Для production-сборки используйте `npm run build`. Telegram Mini App должна
открываться через HTTPS и передавать исходный `initData` backend через
`X-Telegram-Init-Data`. В обычном браузере приложение показывает каркас, но
защищённые API-запросы без Telegram `initData` будут отклонены backend.

Проверка типов и production-сборка запускаются командами `npm run typecheck` и
`npm run build`. Telegram SDK вызывает `ready()` и `expand()`, синхронизирует
светлую/тёмную тему с цветами Mini App, а навигация использует BackButton и
haptic feedback. Раздел магазина и валюта синхронизируются с пользовательскими
настройками backend; без Telegram они сохраняются локально. Корзина и избранное
загружаются через React Query, а действия поддерживают оптимистичные обновления.

Дизайн-система BRAND GRODNO использует CSS-токены в `frontend/src/styles.css`:
секции `men`/`women`, темы `dark`/`light`, акцентные цвета, Manrope и Unbounded,
карточки и поля с радиусом 14 px, а также поддержку `prefers-reduced-motion`.
Основной каркас магазина расположен по адресам `/shop/clothing`, `/shop/shoes`,
`/shop/favorites`, `/shop/cart` и `/shop/profile`. Переиспользуемые компоненты
(Header, BottomNav, Drawer, BottomSheet, ProductCard и остальные элементы)
экспортируются из `frontend/src/components/ui`. Lottie загружается динамически.

Прежние экраны Local Catalog сохранены: главная страница доступна по
`/local-catalog`, а страницы мест, отзывов и формы бизнеса остаются на своих
маршрутах.

## Экраны каталога

Главная страница показывает категории и поиск; список мест поддерживает
бесконечную прокрутку, фильтры по району, рейтингу и графику, а также сортировку.
Карточка места содержит галерею, контакты, график работы, избранное и отзывы.
Избранное и форма предложения бизнеса подключены к соответствующим API.

Фотографии к заявке пока не прикрепляются: для реальной загрузки требуется
настроить файловое хранилище и backend endpoint. Остальные поля формы
проверяются в браузере и сервером.

## Экраны магазина

Первый запуск показывает выбор коллекции; выбранный раздел и валюта синхронизируются
с профилем Telegram-пользователя. Каталог `/shop/clothing` и `/shop/shoes`
использует общий экран с поиском, фильтрами, сортировкой, ценами в выбранной
валюте и подгрузкой страниц при прокрутке. Для списка фильтров доступных размеров
используется публичный `GET /api/store/sizes?group=clothing|shoes`; профиль
покупателя для личного кабинета доступен через авторизованный `GET /api/me`.

Карточка товара и страницы корзины, оформления заказа, профиля и покупок
подключены к существующим Store API. Способы доставки и контакт менеджера
загружаются из публичных настроек магазина; заказ оформляется через
`POST /api/orders`, после чего Mini App открывает сформированную ссылку
менеджера и оставляет кнопку для повторного открытия чата. При разработке
вне Telegram защищённые запросы не выполняются, а вместо них показывается
сообщение об открытии Mini App в Telegram.

## Устранение неполадок

- **Telegram показывает пустой экран или `401`.** Откройте приложение именно
  через меню бота, проверьте HTTPS URL туннеля, убедитесь, что backend и бот
  используют один и тот же новый `BOT_TOKEN`. Перезапустите bot после смены
  `MINI_APP_URL`; проверьте логи API и браузерную консоль.
- **Tunnel показывает `403` или сайт не открывается.** Проверьте, что Vite
  работает на порту 5173 и hostname туннеля заканчивается на
  `.trycloudflare.com`, `.ngrok-free.app` или `.ngrok-free.dev`. Для другого
  домена добавьте его в `server.allowedHosts` в `frontend/vite.config.ts` и
  перезапустите Vite.
- **Каталог не загружает данные / запросы дают `502`.** Проверьте
  `http://localhost:8000/health`, что API запущен, локальная команда выполнена
  с `DATABASE_URL=sqlite+aiosqlite:///./local-catalog.db`, а `python -m
  app.db.dev` завершилась успешно. Для телефона оставьте
  `VITE_API_BASE_URL` пустым, чтобы запросы шли через прокси Vite.
- **Нет доступа к панели.** Сверьте числовой Telegram ID с `ADMIN_IDS` в
  корневом `.env`, перезапустите API после изменения переменной и откройте
  профиль внутри Telegram, а не в обычном браузере.
- **Менеджер или администраторы не получают уведомления.** Проверьте
  `MANAGER_TELEGRAM_ID`, активный процесс бота и логи. Каждый получатель
  должен сам начать диалог с ботом командой `/start`. `manager_username` в
  настройках магазина отдельно управляет ссылкой на чат из заказа.
- **Фото товара не открываются.** Проверьте URL `/uploads/...`; в production
  проверьте, что контейнер API и backup используют volume `uploaded_images`,
  а процесс API может записывать в `UPLOADS_DIR`.
- **Caddy не выпускает сертификат.** Убедитесь, что A-запись уже указывает на
  VPS, порты 80/443 доступны извне, `DOMAIN` совпадает с адресом Mini App, а
  `ACME_EMAIL` задан. Смотрите `docker compose -f docker-compose.yml logs caddy`.
- **Схема локальной SQLite устарела.** `app.db.dev` создаёт таблицы, но не
  применяет Alembic. Для одноразовой локальной базы сначала сохраните нужные
  данные, затем удалите именно `backend/local-catalog.db` и повторите
  инициализацию. Для PostgreSQL используйте Alembic, не удаляйте volume БД.
